# Reminders JSON Interchange — Design Spec

**Date:** 2026-07-18
**Status:** Proposed

**Companion docs:**
- Gateway/MCP build: `docs/superpowers/plans/2026-07-18-reminders-json-interchange.md`
- iOS app build (self-contained handoff, separate project): `docs/superpowers/specs/2026-07-18-reminders-ios-app-handoff.md`

This spec is the protocol's source of truth. The iOS handoff doc restates the wire
protocol from the client's perspective (intentionally duplicated so it needs no
Gateway-repo context); **if the two ever disagree, this spec wins** — update the
handoff doc to match.

## Motivation

Every off-the-shelf reminder app suffers cloud lock-in, and the self-hosted
CalDAV route (Radicale + the NowThis client) has been unreliable: sync bugs, and
no iOS task app does CalDAV-synced geofencing. Rather than keep chasing a client
that fits an awkward protocol, invert it: **Gateway defines a trivial JSON-over-HTTP
protocol, and a purpose-built iOS app talks to it directly.**

This supersedes and retires:

- The Radicale/CalDAV backend for reminders (`gateway/tools/reminders.py` CalDAV impl).
- `scripts/migrate_reminders_to_radicale.py`.
- The plan `docs/superpowers/plans/2026-07-17-location-reminders-owntracks.md`
  (OwnTracks waypoints + `system-owntracks-notify` HA subscriber). Geofencing
  moves on-device into the app; no MQTT, no Home Assistant relay.

Decisions taken with Charlie (2026-07-18):

1. **Storage:** Gateway-native SQLite store; retire Radicale/CalDAV/iCalendar.
2. **Sync:** full-snapshot pull + per-item upsert, **last-write-wins** on `updated_at`, tombstones for deletes.
3. **Geofencing:** native in the app (Core Location region monitoring); the reminder JSON carries a `location` object.

Design north star: **extremely simple**. A reminder is a flat JSON object. Sync is
"send me everything, here are my changes." Auth is one header.

## Architecture

```
┌────────────┐   JSON / HTTPS    ┌─────────────────────────┐
│  iOS app   │ ───Bearer token──▶│  Gateway  /v1/reminders │
│ (SwiftData │◀───snapshot───────│  (Starlette routes)     │
│  mirror +  │                   │            │            │
│  CLRegion  │                   │      reminders/store.py │
│  geofences)│                   │            │            │
└────────────┘                   │        SQLite file      │
                                 └─────────────────────────┘
                                          ▲        ▲
                              MCP tools ──┘        └── gw CLI
                         (create_reminder …)      (gw reminders …)
```

One store, three readers/writers: the HTTP API (phone), the MCP tools
(conversational), and the `gw` CLI — all import `gateway/reminders/store.py`.
No representation is translated; everyone speaks the same reminder object.

The HTTP API is a small Starlette app composed into the existing uvicorn process
in `main.py`, alongside the MCP app. `starlette`/`uvicorn` are already
dependencies; storage is stdlib `sqlite3`. **No new runtime dependencies.**

## The reminder object

A reminder is a flat JSON object. All timestamps are **RFC 3339 UTC** (`Z`).

```json
{
  "id": "3f1c…-uuid",
  "title": "Buy compost",
  "notes": "the peat-free kind",
  "due": "2026-07-20",
  "priority": 0,
  "list": "Reminders",
  "done": false,
  "completed_at": null,
  "location": {
    "name": "Späti, Boxhagener Str.",
    "lat": 52.5200,
    "lon": 13.4050,
    "radius_m": 150,
    "trigger": "arrive"
  },
  "created_at": "2026-07-18T09:15:04Z",
  "updated_at": "2026-07-18T09:15:04Z",
  "deleted": false
}
```

| Field          | Type            | Notes |
|----------------|-----------------|-------|
| `id`           | string (UUID)   | Stable identity. Generated by whichever side creates the reminder. |
| `title`        | string          | Required, non-empty. |
| `notes`        | string \| null  | Free text. |
| `due`          | string \| null  | `YYYY-MM-DD` = all-day (due end of local day); full RFC 3339 = timed. The presence of `T` distinguishes them — no separate flag. |
| `priority`     | int             | `0` none, `1` high, `5` medium, `9` low (matches prior CalDAV mapping). |
| `list`         | string          | List/group name. Default `"Reminders"`. Lists are implicit — created on first use, no separate resource. |
| `done`         | bool            | Completion is a normal field edit, not a special verb. |
| `completed_at` | string \| null  | Set when `done` flips true; cleared when false. |
| `location`     | object \| null  | Geofence. `name` optional human label; `lat`/`lon` authoritative (always present when `location` is set); `trigger` ∈ `"arrive"` \| `"leave"`; `radius_m` default 150. Omitted/null = no geofence. Names are resolved to coords via Nominatim (below) — the stored object always carries coords. |
| `created_at`   | string          | Server- or client-stamped at creation; immutable thereafter. |
| `updated_at`   | string          | **The LWW key.** Set to the writer's wall-clock (UTC) on every edit. |
| `deleted`      | bool            | Tombstone flag. Deleted reminders are retained (see GC below). |

**Reserved for later (not in v1):** `parent_id` (subtasks), `rrule` (recurrence).
Clients must round-trip unknown fields untouched so the format can grow without a
version bump — and **so must the server**. Any JSON key that has no first-class
column is stashed verbatim in the `extra` column (see Storage) and merged back on
read, so `parent_id`, `rrule`, and any future field survive a write→read round-trip
through Gateway rather than being dropped.

## HTTP API (`/v1`)

All requests require `Authorization: Bearer <token>` (see Auth). All bodies are
`application/json`. Errors are `{"error": {"code": "...", "message": "..."}}`.

### Primitives (curl-friendly, also used by CLI/MCP internally)

| Method & path                | Body           | Result |
|------------------------------|----------------|--------|
| `GET /v1/reminders`          | —              | `{ "server_time": "…Z", "reminders": [ … ] }` — full snapshot, **including tombstones**. |
| `GET /v1/reminders?since=…Z` | —              | Same shape, only items with `updated_at > since` (incl. tombstones). Nearly-free optimization; semantics identical. |
| `PUT /v1/reminders/{id}`     | full reminder  | Upsert with LWW (below). `200` + stored object on accept; `409` + **current server object** if incoming is stale. |
| `DELETE /v1/reminders/{id}`  | — (or `{updated_at}`) | Soft-delete: writes a tombstone (`deleted:true`, `updated_at`=now unless supplied). `200` + object. |

### One-shot sync (the app's happy path)

```
POST /v1/reminders/sync
{ "since": "2026-07-18T09:00:00Z" | null,   // null = first sync, send full snapshot
  "changes": [ {reminder}, … ] }            // client's local edits since last sync
→ 200
{ "server_time": "2026-07-18T09:20:11Z",
  "reminders": [ {reminder}, … ],           // everything changed server-side since `since`,
                                            // after applying `changes` (incl. conflict winners)
  "rejected": [ {id, current: {reminder}} ] } // client pushes the server declined (server was newer)
```

`changes` are applied server-side exactly as individual `PUT`s (same LWW rule).
The response then returns the modified-since set, so a full reconcile is **one
round trip**. `rejected` tells the client which of its pushes lost, so it can
adopt the server copy without a second GET.

### Geocoding

Name↔coords reconciliation is Gateway's job, backed by the **already-deployed
local Nominatim** (`composition-nominatim` on server-64gb-storage). This keeps the
iOS app off Apple's (cloud) geocoder — the whole point.

```
GET /v1/geocode?q=Späti+Boxhagener       → { "name": "…", "lat": …, "lon": … }   (best match, or 404)
GET /v1/geocode?lat=52.52&lon=13.40       → { "name": "…", "lat": …, "lon": … }   (reverse)
```

The stored reminder always carries `lat`/`lon`. A `location` submitted with only a
`name` (no coords) is forward-geocoded server-side on write; if it can't be
resolved the write is **rejected** (`400`) rather than silently stored without a
geofence. Clients that already have coords (e.g. from a map pin, or from calling
`/v1/geocode` first) send them directly and skip that step.

## Sync algorithm (last-write-wins)

**Invariant:** `updated_at` is stamped by the *writer* to its local UTC wall-clock
at edit time. The larger `updated_at` always wins. Deletes are edits (tombstones)
and follow the same rule — a later edit can resurrect a reminder, a later delete
buries a later edit, purely by timestamp.

**Server, on receiving a reminder (via `PUT` or a `sync` change):**

```
existing = store.get(id)
if existing is None or incoming.updated_at > existing.updated_at:
    store.upsert(incoming)          # store verbatim, incl. incoming.updated_at
    → accept
else:
    → reject (409 / rejected[]), return existing
```

**Client (app), each sync:**

1. `POST /v1/reminders/sync` with `since` = last `server_time` it saw, and
   `changes` = locally-dirty reminders (each already carrying a fresh
   `updated_at`).
2. Apply every reminder in the response to the local mirror by the same LWW rule
   (remote wins iff its `updated_at` is newer than the local copy).
3. For each `rejected[]`, replace the local copy with `current` and clear its
   dirty flag (this device lost that field's race).
4. Persist the new `server_time` as the next `since`.

**Caveat (documented, accepted):** LWW keyed on writer wall-clocks means clock
skew between devices can pick the "wrong" winner. Single-user, few devices, NTP —
acceptable. No vector clocks, no per-field merge.

**Tombstone GC:** the server may hard-delete tombstones older than **30 days**.
Clients sync far more often than that, so a purged tombstone is never missed. A
client that has been offline > 30 days does a `since=null` full snapshot to
resync from scratch.

## Auth

- Header: `Authorization: Bearer <token>`.
- Config holds a **list** of accepted tokens (one per device, so a lost phone's
  token can be revoked without rotating the others).
- Missing/unknown token → `401`. No token → `401`. Constant-time compare.
- TLS is terminated by the existing reverse proxy in front of Gateway (same as the
  MCP surface); tokens never travel in cleartext off-device.
- **Reachability:** the phone reaches Gateway **over the VPN** — Gateway is not
  exposed to the public internet. The app's base URL is Gateway's VPN address, and
  the bearer token is the second factor behind the VPN. Off-VPN, sync simply pauses;
  the app is offline-first (local mirror is SSOT) and reconciles on next connect.

## Storage

SQLite file at `GATEWAY_REMINDERS__DB_PATH` (default under the service's data dir,
e.g. `~/.local/share/gateway/reminders.db`). Single table:

```sql
CREATE TABLE reminders (
  id           TEXT PRIMARY KEY,
  title        TEXT NOT NULL,
  notes        TEXT,
  due          TEXT,
  priority     INTEGER NOT NULL DEFAULT 0,
  list         TEXT NOT NULL DEFAULT 'Reminders',
  done         INTEGER NOT NULL DEFAULT 0,
  completed_at TEXT,
  loc_name     TEXT,
  loc_lat      REAL,
  loc_lon      REAL,
  loc_radius_m INTEGER,
  loc_trigger  TEXT,               -- 'arrive' | 'leave' | NULL
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL,
  deleted      INTEGER NOT NULL DEFAULT 0,
  extra        TEXT                 -- JSON blob of any keys with no column above
                                    -- (e.g. reserved parent_id/rrule, future fields)
);
CREATE INDEX idx_reminders_updated_at ON reminders(updated_at);
```

`gateway/reminders/store.py` — plain functions over `sqlite3`, the single point
of truth:

- `list_reminders(since=None, include_deleted=False, list_name=None) -> list[dict]`
- `get(id) -> dict | None`
- `upsert(reminder) -> dict` (applies LWW; returns stored object; raises `Stale` if rejected)
- `soft_delete(id, updated_at=None) -> dict`
- `gc_tombstones(older_than_days=30) -> int`
- `_row_to_dict` / `_dict_to_row` handle the `location` object ⇆ flat columns, and
  the `extra` column ⇆ unknown keys: on write, any key not mapped to a column is
  JSON-encoded into `extra`; on read, `extra` is decoded and merged back into the
  top-level object (first-class columns win on any key collision).

WAL mode on; the API, CLI, and MCP tools are all in-process (one uvicorn), so
SQLite's single-writer is a non-issue.

## Gateway changes

**New**

- `gateway/reminders/__init__.py`
- `gateway/reminders/store.py` — SQLite store (above).
- `gateway/reminders/http.py` — Starlette `Route`s for `/v1/reminders…` and
  `/v1/geocode`; bearer auth middleware; thin translation to/from `store.py`.
- `gateway/reminders/geocode.py` — thin httpx client over the local Nominatim
  (`{base}/search?q=&format=jsonv2&limit=1`, `{base}/reverse?lat=&lon=`), returning
  `{name, lat, lon}`. Used by both `create_reminder` and the `/v1/geocode` route.
- `scripts/migrate_radicale_to_sqlite.py` — one-shot: read VTODOs via `caldav`,
  parse the old `[location: …]` text markers into `location` objects
  (forward-geocoding the place name via `geocode.py`), insert rows.

**Rewritten**

- `gateway/tools/reminders.py` — MCP tools keep their names/signatures
  (`create_reminder`, `list_reminders`, `complete_reminder`, `delete_reminder`,
  `search_reminders`, `list_reminder_lists`) but call `store.py` instead of
  CalDAV. `create_reminder` keeps its `location_name`/`arrive_or_leave` params and
  now forward-geocodes `location_name` via `geocode.py` into a real `location`
  object (lat/lon/radius/trigger); it errors if the name won't resolve. The old
  text-marker hack is gone.
- `gateway/cli/commands/reminders.py` / `fmt.py` — show the `location` object;
  add `--radius`. Otherwise unchanged surface.
- `gateway/config.py` — see below.
- `gateway/main.py` — mount `reminders.http` routes into the served app next to
  the MCP app; call `store.init(config.reminders)`.

**Retired**

- CalDAV client code in `tools/reminders.py`; `scripts/migrate_reminders_to_radicale.py`.
- `caldav`/`icalendar` become migration-only (dev) deps, droppable after cutover.
- The OwnTracks-waypoint / HA-notify plan (see Motivation). `tools/owntracks.py`
  stays for *location tracking*; it no longer publishes waypoints.

## iOS client contract (app to be built)

The full, self-contained build brief lives in
`docs/superpowers/specs/2026-07-18-reminders-ios-app-handoff.md` — a **fresh,
from-scratch app in a separate project**, no NowThis carryover. It restates this
protocol from the client's side and specifies the local model, sync loop,
geofencing, notifications, UI scope, and acceptance tests. In brief, the format
obliges the client to: keep an offline-first local mirror (SSOT) with a `dirty`
flag; sync via `POST /v1/reminders/sync` (LWW, algorithm above); store base URL +
bearer token in Keychain; do on-device geofencing (`CLCircularRegion`, nearest-20
cap); resolve names→coords via `GET /v1/geocode` (never `CLGeocoder`); and preserve
unknown JSON fields.

## Non-goals (v1)

- Multi-user / sharing / ACLs. Subtasks & recurrence (fields reserved only).
- Real-time push (poll-based sync only).
- Per-field merge / vector clocks (whole-object LWW only).
